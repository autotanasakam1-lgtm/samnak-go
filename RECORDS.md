# ประวัติการเล่นและดูย้อนหลัง

กด **ประวัติ** ที่เมนูหลัก แล้วเลือกประเภทเกมหรือคู่ประลอง กด **ดูย้อนหลัง** ใต้เกมที่ต้องการ ใช้ปุ่มก่อนหน้า ถัดไป เริ่ม สุดท้าย หรือเล่นอัตโนมัติได้ เลื่อนแถบเพื่อไปยังตาที่ต้องการ ดูจำนวนหมากดำและขาวได้ทั้งบนโทรศัพท์และคอมพิวเตอร์

เกมของคุณ รวมเกมเล่นกับเพื่อน เก็บไว้ในเครื่องนี้ เกมที่ถอยจะแสดงจำนวนครั้งและเปิดดูหมากที่เอากลับได้ กด **เริ่มเกมใหม่** ระหว่างเล่นเพื่อเก็บเกมเดิมก่อนเริ่มใหม่ พร้อมแสดงฝ่ายที่นำโดยประมาณ การนับอย่างง่ายยังไม่ใช่ผลสุดท้าย

เกมทดสอบคอมมีตัวอย่างเล็กสองเกม ระบุว่า **เกมตัวอย่าง** และซ่อนหรือแสดงได้ด้วยปุ่มบนหน้านี้ ตัวอย่างไม่รวมในสถิติจริง เจ้าของดูทุกอย่างโดยคลิกในเว็บ ไม่ต้องเปิดไฟล์หรือใช้คำสั่ง

การส่งผลส่วนกลางปิดไว้ ชื่อคู่ประลองเป็นตัวละครสมมติ คลังแนวคิดฝึกไม่มีชื่อหรือประวัติครูจริง ใช้ชื่อเล่นสำหรับชื่อผู้เล่น

## Technical notes

- Source modules: `src/record-logic.js` (shared parser and audit), `src/record-hooks.js` (human game integration), `src/records.js` (lazy list/replay). No new runtime dependencies. Bot data is fetched only on entering Records. Replay uses the existing `Go` rules and `drawBoard` SVG.
- Build: `node tools/build-records.js`, then `node tools/build-site.js`. The latter regenerates the tracked root `index.html` with the existing inline bundle structure. The original `src/build.sh` also includes the modules and copies bot data into its `src/site/records/` output. Publish the root `records/bot-games.json` alongside `index.html` for root deployment. Nothing was pushed.
- Converter reads `calib/handicap-results.json`, `sensei[sid].games[]`, and relative `handicap-sgf/*.sgf` paths, matching `pc-files/calib-handicap.js`. Outputs compact `records/bot-games.json`. Handles setup stones (`AB`, `AW`, rectangular setup ranges), explicit move colors, passes, result/margin/resignation, and engine adjudication. Rejects variations, invalid sizes/coordinates, and paths escaping the SGF directory. Input player names/comments are not published; opponent names come from the fictional SENSEI allowlist. Summaries are by opponent and handicap; wins refer to the black sensei. Invalid games and samples are excluded from statistics.
- Samples live in `records/samples.json`. Delete that file and rerun the converter to remove them permanently; the owner can hide them in the UI without editing files.
- Human records use existing `store`/localStorage under `go-records`. Each audit keeps chronological moves and undo events; removed moves remain replayable. Undo count counts requests, while each request separately records how many moves were removed, the requesting side, and the move reached. The replay slider traverses chronological events, so move numbers can decrease after an undo. Bot test records never undo.
- Active-game `go-game` now carries a version-2 audit. Old saves reconstruct the available move history and start with no known undo events. Existing `go-log` SGF games are adapted at display time and explicitly say undo information is unavailable. New finished records link to old result-log entries to avoid duplicate rows. Existing progress remains intact. The existing UI backup/restore includes the new records. Local records persist until browser data is cleared or a backup replaces them.
- Restart records include `restarted`, `moveReached`, `leader`, `leadMargin`, `leadMethod`, `undoCount`, `undos`, and the full chronological events. Explicit restart uses existing engine `lead` when available; otherwise area count including white compensation. Replacing/discarding a paused game uses area count. Starting another game preserves the abandoned record, including after reloading the page.
- `REPORT_URL` in `src/report.js` is empty. Transmission still requires both a configured URL and user opt-in. Existing game payloads carry `undoCount`, `undos`, and `restarted`; separate `record` events cover friend games and restarts. Both Apps Script source copies support the extra columns and a separate records sheet. Existing server request/cell size limits still apply; exceptionally long histories may exceed those limits. No server was contacted or deployed.
- Removed the pre-existing real-person gallery from bundled site data; replaced it with anonymous learning concepts. Converter discards external SGF names/comments. The app has no dedicated field for teacher identity. User-entered nicknames and puzzle text remain user-controlled.
- Verification: `node src/test.js`, `node tools/test-records.js`, `node tools/test-record-view.js`; syntax compilation of all source JavaScript and the generated inline bundle. The view smoke test simulates DOM controls (list, filtering, handicap setup, next/end, stone counts). No available in-folder headless-browser setup was found, so real browser layout/console verification remains a manual check. Existing responsive board/stage CSS is reused, and portrait/landscape navigation was expanded to five items.
